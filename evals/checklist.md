# 执行检查清单（Eval Checklist）

本清单用于验证 SDD+TDD 流程执行是否符合规范。每个阶段完成后对照检查。

## Epic 启动检查

- [ ] Project Spec（North Star）存在且是最新版
- [ ] 变更影响分析已完成（改什么、影响什么、什么不能动）
- [ ] Epic Spec 已创建，包含需求背景、目标、范围、子系统职责
- [ ] 四轮迭代计划已规划
- [ ] 第 0 轮环境验证 Issue 已创建

## Issue 派发检查

- [ ] Issue 自包含（目标、约束、前置依赖、用例清单）
- [ ] subagent 上下文最小化（不加载完整 Epic 或全部代码）
- [ ] 前序 Issue 的交接清单已准备好
- [ ] Issue 内的约束已从 Project/Epic Spec 中筛选相关的

## Issue 执行检查（subagent）

- [ ] 先调查现有实现，不盲目写测试
- [ ] 设计未明确时先形成局部设计
- [ ] 按用例顺序逐条执行 TDD 循环
- [ ] 每条用例：红灯确认失败 → 绿灯最小实现 → 微重构
- [ ] 发现超出范围的问题记入待上浮项，不硬扛
- [ ] 全量回归测试通过
- [ ] 覆盖率达标
- [ ] 交接清单完整
- [ ] 待重构清单已记录

## Issue 回收检查（主 Agent）

- [ ] 验收结论明确（通过/有条件通过/不通过）
- [ ] 问题清单已记录
- [ ] Epic Spec 状态和进度已更新
- [ ] 交接记录已更新
- [ ] 待上浮项已汇总到 Epic Spec
- [ ] 待重构清单已更新

## 轮次结束检查

- [ ] 全量回归测试通过
- [ ] 轮次目标达成
- [ ] 待上浮项已处理（更新 Epic Spec 或上浮到 Project Spec）
- [ ] 全局待重构清单已处理
- [ ] 覆盖率报告已生成
- [ ] 下一轮 Issue 已准备
- [ ] 如需更新 Project Spec，版本号和变更记录已更新

## 文档质量检查

- [ ] Project Spec 只写长期约束，不写实现细节
- [ ] Epic Spec 只写本次需求，不重复 Project Spec
- [ ] Issue 只写当前推进需要的，不重复 Epic Spec
- [ ] 代码里能查到的实现细节没有写进文档
- [ ] 所有文档状态和进度是最新的

## 常见反模式检查

- [ ] 没有跳过第 0 轮环境验证
- [ ] 没有在 Issue 内硬扛全局/架构级问题
- [ ] 没有把重构无限期推迟
- [ ] 没有一次性生成完整设计文档（瀑布式）
- [ ] 没有让 subagent 加载过多上下文
- [ ] 没有为了形式完整而为简单 Bug 创建 Epic
