# 有界执行与停止预算

派发 subagent、调查未知项、反复修复测试或执行审查时读取。预算用于暴露停滞，不用于掩盖未完成工作。

## 1. 每次派发必须声明

- 单一目标和允许写入范围。
- 完成条件与必须返回的证据。
- 最大输出：默认只读报告 1200 中文字、实现/修复摘要 1600 中文字；diff 和日志使用路径，不粘贴全文。所有 blocker/major 必须完整返回；超出预算时省略或归组 minor/note，并说明被归组数量。
- 超时：宿主支持时必须设置。默认只读调查/审查 15 分钟，实现/修复/验证 30 分钟；扩大一次必须在 Task 记录理由。到达期限仍在运行且宿主支持中断时，由主 Agent 中断并按超时恢复处理。
- 尝试预算和停止条件。

大型 Issue 不通过持续增加超时解决。先按行为、模块或风险拆分 Context Pack；无法拆分时建立独立集成 Gate。

## 2. 停滞判定

以下任一情况视为没有取得新证据：

- 同一命令以同一根因连续失败。
- 重复读取同一范围但没有新增事实、排除项或可验证假设。
- 修复只移动症状，Requirement/Test 状态没有变化。
- subagent 返回的仍是相同缺口，且主 Agent 没有补充新 Context。

同一根因连续两次没有新证据时停止当前尝试并重新规划。重新规划后再失败一次，标记 blocked、保存最后证据，并拆 Issue 或询问真正需要用户决定的内容。不能用改写措辞把相同尝试计为新方案。

## 3. 分阶段默认预算

| 阶段 | 默认尝试边界 | 预算耗尽后的动作 |
|---|---|---|
| Explore 事实调查 | 定向调查 + 一次扩大范围 | 标记 verified/inferred/unknown；阻塞项进入 Grill |
| subagent 派发 | 首次派发 + 一次补充 Context | 缩小任务、换独立任务或由主 Agent 接管；不原样重派 |
| TDD/实现失败 | 同一根因两次无新证据后重规划一次 | blocked 或拆分 Issue |
| Verification 环境失败 | 一次诊断 + 一次针对性重试 | 分类 environment/unknown，不能宣称通过 |
| Review | 初审 + 最多两轮修复复审 | 按 review-loop 标记 blocked |
| Writeback 冲突 | 一次重读当前版本并合并 | 标记 conflict/needs_decision |

用户回答新的决策、仓库发生相关变化或加入新证据后，可以开启新的预算周期；必须在 Task/Closure 记录触发原因。

## 4. 超时与中断恢复

超时不是失败结论。保留已读取范围、已修改文件、最后命令、未完成条件和下一最小动作。主 Agent 核对工作区后决定继续、缩小、拆分或阻塞。不得因 subagent 超时重复派发同一无界 prompt。

## 5. 完成条件

每个仍在运行或重试的动作都有目标、证据、尝试次数和停止条件；达到预算后必然进入缩小、拆分、blocked 或用户决策之一，不存在无界重试。
